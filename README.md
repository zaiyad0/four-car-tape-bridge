# 四车协同 · 卷尺桥

四台麦轮车各自放卷一卷卷尺，伸到对面吸合，拼成一座桥。

难点不在「四台车各走各的」，而在**四台车必须同时到位**才能吸合——而电池电量、
地面摩擦、开机时间每台都不一样。**用时间做判据必然失败**，所以整套编排是条件驱动的。

## 设计要点

**① 全程条件驱动，不用 `sleep`**

| ❌ 时间驱动 | ✅ 条件驱动 |
|---|---|
| `time.sleep(5)` | `wait_until(lambda: odo.driven(3.0))` |
| `turn_left(90)` | `wait_until(lambda: odo.headed_to(90, 2.0))` |
| `extend_tape()` | `wait_until(lambda: all_cars_report('ALIGNED'))` |

**② 主机是计数器，不是控制器**

每台车自己判断「我到没到位」（编码器里程 / IMU 航向），主机只数状态上报的个数。
——所以加第 5 台车不用改主机逻辑。

**③ 周期重发 + 超时兜底**

状态上报和指令广播都周期重发：丢一包 `GO`，那台车就一直停在 `READY`，整队卡死。
`mission_timeout` 到期广播 `ABORT`，避免四台车一起僵住。

## 代码

[`four_car_ws/`](four_car_ws/) 是 ROS 2 工作空间，5 个功能包：

| 包 | 职责 |
|---|---|
| `car_base` | 麦轮正逆解算、里程计 + IMU 融合、ZDT_M370 串口协议（含减速比自适应、单应答优化） |
| `car_arm` | 卷尺放卷控制、电磁铁 + 霍尔、总线舵机、L298N |
| `car_agent` | 单车状态机 |
| `mission_controller` | 集中编排 |
| `four_car_bringup` | launch 文件 + `config/params.yaml`（所有可调参数集中在这） |

**不需要 ROS、不需要硬件就能跑自测**（麦轮解算 / 里程计 / 卷尺三块数学）：

```bash
cd four_car_ws
python selftest.py        # 29/29 通过
```

## 硬件

树莓派 5 × 4，麦轮底盘（ZDT_M370 闭环伺服 + 串口），放卷式卷尺 + 电磁铁吸合。
4 台车与主机同一 `ROS_DOMAIN_ID`，跨机通信走 WiFi。

驱动按器件手册实现；硬件到位后需标定两项：**实测直行距离**和**PWM 引脚接法**（见 `params.yaml` 中标注处）。
